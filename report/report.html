Chapter 1

Executive Summary

What the system is, the problem it addresses, and who it serves — written for a reader with no prior exposure to it and no electrical background.

1.1 What the dashboard is

Power Monitor is a web-based electricity management dashboard for the AOR complex at GE(N) Maint Isld — a 360-acre site containing 2,157 buildings, three electrical substations and 109 transformers. It presents, on a single set of screens, how much electrical power every part of the site is drawing, whether any part is drawing more than it should, and what the electrical supply quality looks like.

The dashboard displays 110 monitored locations, each identified by a stable tag such as TW-01 (Tube Well No.1) or MED-HOSP (PNS Hafeez Hospital). Each location has a defined consumption limit. When a location exceeds that limit, the system raises an alarm that persists until an operator acknowledges it.IMPL

1.2 The problem it addresses

Before a system like this exists, a facility of this size has an inventory but no visibility. The maintenance organisation knows it is responsible for 980 street lights, 84 motor pumps and 14 tube wells, but it cannot answer three practical questions:

  • Where is our electricity going? Which zones, buildings and plant items account for the site's consumption.
  • Is anything abnormal right now? A pump drawing double its normal current is a failing bearing; nobody notices until it seizes.
  • Do we have capacity? Whether a new building can be connected to an existing substation without overloading it.

The dashboard is built to answer all three continuously rather than through periodic manual survey.

Critical qualification — read before using any figure

The source document for this project is an asset register: it records what exists and in what quantity. It contains no electrical measurements of any kind. A systematic search of the document returns zero occurrences of voltage, frequency, power factor, kWh, MVAR, generator, incomer, breaker, meter or demand.IMPL

Consequently every live reading shown by the dashboard is simulated, and is labelled as such in the interface. The structure — asset counts, transformer capacities, named locations, network topology — is real and traceable to the register. The readings are a working model awaiting connection to real metering.

The dashboard follows a summary-then-detail structure. One screen answers "is anything wrong?"; eleven further screens answer "what, where, and why?". This mirrors how a control room is actually used: continuous monitoring of a single overview, with drill-down only when something demands attention.INTERP

2.3 Persistent header

The header remains constant across all twelve screens. Its most operationally significant element is the connection pill, which reports both the feed state and the age of the most recent message. A dashboard that silently freezes on stale values is the most dangerous failure mode this class of system has; the header is where that condition is made visible.INTERP

This bar is unusual for a dashboard and deserves comment. Because the register contains no metering, the interface would otherwise present modelled values with the same authority as measured ones. 2.6 How the parts work together

All twelve screens read from the same three in-memory models, so no two screens can disagree about the state of the plant:IMPL

  • The store holds smoothed readings, per-point history, and roll-ups by group and by substation.
  • The electrical model derives voltage, current, power factor, reactive power and energy from those readings.
  • The alarm engine evaluates every reading against its limits and maintains the alarm record.

A single render loop updates whichever screen is currently displayed, once per second. Screens that are not displayed are not rendered.

3.4 Runtime behaviour

2,000 ms default; configurable via --interval.
Render interval
1,000 ms, fixed and independent of the feed rate.
Source detection
On load the application probes ./api/health with a 2.5 s timeout. If it responds, the stream is used; otherwise the in-browser simulator runs.

localStorage retains only theme, display density and last-viewed screen. No readings are persisted.
Design note — why rendering is decoupled from the feed

The render loop runs on a fixed timer rather than on data arrival. A fast feed therefore cannot overwhelm the interface, and — more importantly — a feed that stops still triggers repaints. This is what allows staleness, offline meters and a dead backend to surface on their own, instead of the display freezing on the last good value while appearing healthy.IMPL

4.3 The payload contract

Both transports carry an identical structure. This is the contract a real SCADA gateway must satisfy:IMPL

{ "ts": 1785755194099, // epoch ms, when the frame was assembled "daylight": true, // optional; gates solar under-performance limits "readings": [ { "id": "TW-01", // must match a tag in register.js "kW": 14.8, // instantaneous demand; generation is POSITIVE "ts": 1785755194099, // when sampled AT THE METER, not on arrival "quality": "good" } // "good" | "bad" ] }
Contract rule — unreachable meters

A meter that cannot be reached must be omitted from the readings array entirely. It must never be sent as 0. The dashboard distinguishes "offline" from "drawing nothing", and transmitting zeros would destroy that distinction — a genuinely dead circuit and a failed communications link would become indistinguishable.IMPL

4.4 Connecting real telemetry

Because every screen reads from the models rather than the feed, replacing simulated data with real data requires changing one module. In src/app.js the source is constructed with a mode and two URLs; pointing those at a real gateway is sufficient. The source mode is also switchable at runtime from the header.IMPL

The reader is tolerant of common field-name variants — tag or pointId for id, kw or value for kW, timestamp for ts — which reduces the amount of adaptation a gateway needs.IMPL

Chapter 5

Screen Analysis — Overview

The first of twelve screen analyses. Each follows the same structure: purpose, rationale, information provided, mechanism, interpretation, and a practical use case. Every major section within the screen is documented individually.

5.1 Purpose

To answer one question without scrolling and without interaction: is the site healthy right now? This is the screen intended to remain permanently displayed on a wall-mounted monitor.

5.2 Why this screen exists

Continuous monitoring only works if the normal state is legible at a glance from across a room. If an operator must read numbers or navigate to establish that nothing is wrong, the monitoring is not continuous — it is periodic inspection. The Overview compresses six headline electrical parameters, the alarm state, the network diagram and the supply-quality trace into a single view.INTERP

Contents

5.4 How it works

All Overview content is rendered by src/overview.js, called once per second from the render loop while this screen is displayed. 5.5 How to interpret it

  1. Check the four status indicators in the KPI strip. Green across means supply quality is acceptable.
  2. Check the alarm panel. Empty means no location is over limit.
  3. Glance at the load trend — is the solid line near the dashed one?
  4. Glance at the single-line diagram — are all three substation boxes outlined neutrally?

If all four checks pass, no further inspection is warranted.

5.6 Practical use case

An operator on shift notices the alarm panel now shows one amber entry: ADM-TWR-C6C7 — consumption 267 kW exceeds the 246 kW warning limit by 9%. Glancing at the single-line diagram, the NHQ substation box is outlined amber, confirming the affected load sits on that substation. The KPI strip still shows frequency and voltage normal, so this is a load problem rather than a supply problem. The operator acknowledges the alarm and moves to Load Monitoring to examine the tower's trend.

Chapter 6

Screen Analysis — Power Flow

Where the electricity goes, traced from intake to consuming group.

6.1 Purpose

To show the distribution of power from its sources, through the 11 kV bus and the three substations, to the asset groups that consume it — with quantities represented proportionally rather than only stated numerically.

6.2 Why this screen exists

A table of group consumption tells you the numbers but not the structure. A flow diagram shows both simultaneously: which substation feeds which groups, and how much of the total each path carries. For explaining the site to someone unfamiliar with it, and for narrowing a fault to a supply path, the structural view is faster than any table.INTERP

6.3 Sections

6.3.1 Stat tiles

Purpose
Quantify the flow in four figures before the diagram is read.
Calculation
Losses = total demand × (100 − efficiency) ÷ 100. Efficiency derives from the demand-dependent loss fraction in the electrical model.IMPL
Unit
MW for demand and solar, kW for losses, percent for efficiency.

6.3.2 Flow diagram

Purpose
Represent power distribution as proportional flow.
Data used
Sources from site load and generation; substation and group values from store roll-ups; each substation links only to groups that actually contain points fed by it.IMPL
Visualisation logic
Ribbon thickness = (value ÷ total input) × 34 px, with a 1.5 px floor so small flows remain visible.IMPL
Interpretation
Follow any ribbon from left to right to see the complete path. Thickness comparison between ribbons is the intended reading; exact values are labelled on each node.
Significance
Makes the dominance of residential load immediately apparent without arithmetic.

6.3.3 Feeder loading

Purpose
Show how hard each feeder is working relative to what it can carry.
Calculation
Loading % = feeder load ÷ substation capacity × 100, where capacity = installed kVA × 0.9.IMPL
Status
Amber above 80%, red above 90%.
Interpretation
Typical values sit between 20% and 45%, which is normal distribution-transformer loading. Sustained values above 80% indicate a capacity constraint.

6.4 How to interpret it

Read left to right. The two source nodes should sum to the bus figure. Substation ribbons should be proportionate to the substation loads shown elsewhere. Any substation whose box is outlined amber or red holds an alarm on one of its loads.

6.5 Practical use case

A planner is asked whether a new accommodation block can be fed from the ARC substation. The feeder bars show ARC running at roughly 20% of its 2,880 kW capacity — approximately 2,300 kW of headroom. The flow diagram confirms ARC currently feeds the water, lighting and vertical-transport groups, so the new block would introduce a residential profile onto a feeder that presently carries none, changing its daily shape.

7.5 Practical use case

KPI & Metrics Reference

The six headline KPIs documented in full, followed by a complete reference table covering every remaining metric in the interface.

16.1 The six headline KPIs

Total Active Power

Definition
The rate at which the site is consuming useful electrical energy at this instant.
Simple
How fast the whole site is using electricity right now — the speedometer, not the odometer.
Technical
Real power: the component of supplied power performing actual work, as opposed to reactive power which circulates without doing work.
Unit
MW on the tile; kW in the sub-line. 1 MW = 1,000 kW.
Purpose
The single most important operational number — the basis of capacity and cost.
Why included
Every other consumption figure is a subdivision of this one.
Data source
Sum of smoothed readings across all monitored non-generation points.IMPL
Calculation
site.kw = Σ smoothed kW of all load points
Example
4,526 kW displays as 4.53 MW.
Interpretation
Typical 3,000–5,500 kW depending on hour. Judge against typical for this hour, not against a fixed threshold — 4,500 kW is normal at 20:00 and abnormal at 04:00.
Relationships
Integrated over time gives Energy. Divided by voltage and power factor gives Current. Combined with reactive power gives apparent power.

Reactive Power

Definition
Power that oscillates between source and load without performing net work.
Simple
Electricity that sloshes back and forth. Motors and transformers need it to build magnetic fields, but it does no useful work and still occupies cable capacity.
Technical
The imaginary component of complex power, arising from the phase displacement between voltage and current in inductive loads.
Unit
MVAR on the tile (megavolt-ampere reactive); kVAr per substation.
Purpose
High reactive power means cables and transformers carry current that produces nothing, and utilities commonly penalise it.
Data source
Derived from real power and power factor per substation, then summed.IMPL
Calculation
Q = P × tan(arccos(PF)) per substation; site total is the sum.
Example
P = 3,319 kW at PF 0.95 gives Q = 3,319 × tan(arccos 0.95) = 1,091 kVAr.
Interpretation
Rises as power factor falls. Typically 25–35% of real power on a motor-heavy site. A sharp rise with no corresponding rise in real power indicates increased inductive load or failing power-factor correction.
Relationships
Directly determined by power factor; combines with real power to give apparent power.

Power Factor

Definition
The ratio of real power to apparent power — how efficiently supplied power is converted into useful work.
Simple
A score from 0 to 1. 1.0 means every unit supplied does useful work. 0.8 means a fifth of the capacity is wasted moving reactive power around.
Technical
The cosine of the phase angle between voltage and current waveforms.
Unit
Dimensionless, 0 to 1. Displayed to three decimal places.
Purpose
Improving power factor is frequently the cheapest available saving on an industrial site.
Data source
Computed site-wide from real and apparent power.IMPL
Calculation
PF = P ÷ S where S = √(P² + Q²)
Example
P = 4,526 kW, Q = 1,420 kVAr gives S = 4,744 kVA and PF = 0.954.
Interpretation
Above 0.95 good. 0.90–0.95 acceptable. Below 0.90 usually attracts a penalty and the tile shows a warning. Falls as motor load rises — a normal daily variation, not a fault.
Relationships
Governs reactive power and current. For the same real power, a lower power factor means more current and higher losses.

Frequency

Definition
The rate at which alternating current reverses direction.
Simple
How many times per second the electricity changes direction. It must stay very close to 50 — it is a live indicator of whether national generation is keeping up with national demand.
Technical
The fundamental frequency of the supply waveform, determined by the rotational speed of synchronous generators across the interconnected grid.
Unit
Hz (hertz), two decimal places.
Purpose
Sensitive equipment and motor speeds depend on it; sustained excursion signals grid instability.
Data source
Modelled as a slow wander about 50 Hz, identical at every bus because frequency is a system-wide quantity.IMPL
Calculation
f = clamp(50 + 0.045·sin(φ) + noise, 49.7, 50.3)
Interpretation
Statutory band 49.5–50.5 Hz. Below 49.5 means demand exceeds generation nationally; above 50.5 the reverse. A site cannot influence this, only respond to it.DOMAIN
Relationships
Independent of site load. Unlike every other KPI, it reports on the grid rather than on the site.

Average Voltage (L-L)

Definition
Mean line-to-line voltage across the three substations.
Simple
The electrical "pressure" pushing current through the wires. Too low and motors overheat; too high and insulation degrades.
Technical
RMS potential difference between any two of the three phase conductors, averaged across the phases and then across the substations.
Unit
kV (kilovolts), two decimal places. Nominal 11 kV.
Purpose
Out-of-band voltage shortens equipment life without ever causing an outage.
Data source
Derived per bus with a load-dependent droop and a small independent per-phase offset, then averaged.IMPL
Calculation
Vphase = 11 × (1 − loading×0.028 + imbalance + noise)
Example
Phases at 10.962, 10.905 and 10.875 kV average to 10.91 kV — within band.
Interpretation
Band 10.5–11.5 kV (±4.5%). Voltage falling as load rises is normal droop. Voltage below band at high load indicates an undersized or overloaded supply path.
Relationships
Falls as loading rises; determines current for a given power; underpins the phase-imbalance calculation.

Energy Today

Definition
Total electrical energy consumed since monitoring began.
Simple
The odometer to Total Active Power's speedometer. This is what an electricity bill charges for.
Technical
The time integral of real power over the measurement period.
Unit
kWh below 1,000, MWh above. 1 MWh = 1,000 kWh.
Purpose
The billing quantity and the basis of any consumption-reduction target.
Data source
Accumulated on every ingest from smoothed power and elapsed time.IMPL
Calculation
E += P × Δt ÷ 3,600,000 with Δt in milliseconds, rejecting gaps over 60 s.
Example
4,500 kW sustained for 2 seconds adds 4,500 × 2,000 ÷ 3,600,000 = 2.5 kWh.
Interpretation
Monotonically increasing. Its rate of increase is average demand. Judge against the expected-for-elapsed reference on the gauge, not in isolation.
Relationships
Power × time. Divided by elapsed hours gives average demand; with peak demand gives load factor; with the emission factor gives CO₂.

Chapter 17

Technical Terminology

The terms and abbreviations appearing in the interface, each explained first in plain language and then technically. Only terms actually present in the dashboard are included.

17.1 Power and energy terms

kW — kilowatt

Simple: a measure of how fast electricity is being used. A domestic kettle draws about 2 kW. Technical: one thousand watts; the SI unit of power, being energy transfer per unit time. Unit of: power. Measured: in this implementation, reported per point by the feed and summed. Why it matters: it is the fundamental quantity every consumption figure is built from. Interpretation: a rate, not a quantity — meaningful only at an instant. Example: a tube well pump drawing 15 kW.

MW — megawatt

Simple: one million watts, used because site totals in kW become unwieldy. Technical: 1 MW = 1,000 kW. Why it appears: the KPI tiles display site totals in MW for legibility while retaining kW in the sub-line. Example: 4,526 kW shown as 4.53 MW.

kWh — kilowatt-hour

Simple: the amount of electricity used, as opposed to how fast. One kilowatt sustained for one hour. Technical: a unit of energy equal to 3.6 megajoules. Formula: E (kWh) = P (kW) × t (h). Why it matters: this is the billing unit. Interpretation: always increasing; its rate of increase is average power. Example: a 10 kW pump running 5 hours consumes 50 kWh.

MWh — megawatt-hour

1,000 kWh. The dashboard switches automatically from kWh to MWh above 1,000 kWh to keep the displayed figure readable.IMPL

kVA and MVA — kilovolt-ampere

Simple: the total electrical load a cable or transformer must physically carry, including the part that does no useful work. Technical: apparent power, the vector sum of real and reactive power. Formula: S = √(P² + Q²). Why it appears: transformers are rated in kVA, so all capacity figures in the register are in kVA. Example: the site's 109 transformers total 18,530 kVA.

kVAr and MVAR — reactive volt-ampere

Simple: the portion of power that does no work but is still required by motors and transformers. Technical: the imaginary component of complex power. Formula: Q = P × tan(arccos PF). Interpretation: the lower the power factor, the higher this is for the same useful output.

17.2 Supply quality terms

V, kV — volt, kilovolt

Simple: electrical pressure. Technical: potential difference. In this system: 11 kV high-tension distribution — evidenced by the register's "VCBs HT 11 KV" entry — stepped down to 400 V for buildings.IMPL

L-L — line-to-line

Voltage measured between two phase conductors rather than between one phase and earth. The standard way to quote three-phase voltage, which is why the dashboard labels its voltage figures "L-L".

A — ampere

Simple: how much electricity is flowing. Technical: the SI unit of current. Formula used: I = P ÷ (√3 · V · PF) for a three-phase system. Why it matters: cables are sized by current; exceeding their rating overheats them.

Hz — hertz

Simple: cycles per second. Technical: the supply's fundamental frequency, nominally 50 Hz in this region. Interpretation: a grid-level quantity that a site observes rather than controls.

PF — power factor

Covered fully in Chapter 16. In brief: the ratio of useful power to total supplied power, between 0 and 1.

R-Y, Y-B, B-R — phase pairs

Simple: industrial supply uses three live conductors, coloured Red, Yellow and Blue. These three labels are the three possible pairings between them. Technical: the three line-to-line voltage measurements of a three-phase system. Why they appear: the voltage profile plots all three so imbalance between them is visible.

Phase imbalance

Simple: the three phases carrying noticeably different loads. Formula: maximum phase deviation from the mean, divided by the mean. Why it matters: sustained imbalance overheats and destroys three-phase motors. Interpretation: below 2% acceptable.

17.3 Network terms

HT / LT — high tension / low tension

High-voltage distribution (11 kV here) and low-voltage final distribution (400 V). Electricity travels at high voltage because losses fall as voltage rises for the same power. The register records 38 km of HT and 108 km of LT cable.IMPL

Substation

Where high voltage is received and stepped down for local distribution. Three exist: PNS Hafeez, ARC and NHQ, plus 13 satellite stations serving outstations.

Transformer

Simple: the device that changes voltage from high to low. Technical: a static machine coupling two windings by a magnetic field. Rated in: kVA. Example: a 200 kVA unit carries roughly 180 kW of real load at 0.9 power factor.

Feeder

A cable circuit carrying power from a substation to a group of loads. The register states three feeders; the dashboard models one per substation.

Busbar

The heavy conductor inside a substation to which everything connects — the common junction between incoming supply and outgoing feeders. Drawn as the horizontal line on the single-line diagram.

VCB — vacuum circuit breaker

Simple: an automatic switch that disconnects a circuit when something goes wrong. Technical: a breaker interrupting current within a vacuum chamber, which extinguishes the arc cleanly; standard at medium voltage. In this system: eight units at 11 kV across four register-named sites.IMPL

DB — distribution board

The panel of protective devices inside a building splitting incoming supply into final circuits — a domestic consumer unit, scaled up. The register records 475 with no further detail.

SLD — single-line diagram

The standard engineering drawing of an electrical network, representing each three-phase circuit as one line. Universally read by electrical engineers, which is why the dashboard uses this form rather than a generic chart.

Solar PV / kWp

Photovoltaic panels generating electricity from sunlight. kWp is "kilowatt peak" — output under full reference sun. The register states 13 systems but gives no ratings.IMPL

17.4 Load and capacity terms

Load

Any device or group of devices consuming electricity; also the amount consumed. The dashboard uses it in both senses — "load group" (the devices) and "site load" (the amount).

Demand

Power drawn at a given moment. Essentially interchangeable with load in this context.

Peak demand

The highest demand reached in a period. Commercially significant because utilities frequently levy a charge based on it, independent of total energy.DOMAIN

Connected load vs demand

Connected load is the total that could be switched on at once; demand is what is actually drawn. Connected capacity here is 16.7 MW while typical demand is around 4.5 MW.

Diversity

The reason for that gap. Across 2,157 buildings, not everything runs simultaneously, so the real total sits far below the theoretical maximum. This is why networks are not sized to connected load.DOMAIN

Capacity / firm capacity

The load the network can carry safely and continuously, derived here from installed transformer kVA at an assumed 0.9 power factor.

Utilisation

Load as a percentage of capacity. Distribution transformers typically run at 30–60%.

Load profile

The characteristic shape of demand across a day. Residential load peaks in the evening; office load at midday; street lighting runs only at night. Each asset group in the register carries its own profile.IMPL

Generation

Electricity produced on site rather than imported. Here this means solar only — the register records no generators of any kind.IMPL

17.5 Monitoring and alarm terms

SCADA

Full form: Supervisory Control and Data Acquisition. Simple: the standard family of industrial systems that collect readings from field equipment and present them centrally. In this system: the dashboard is designed to sit on top of one; the reference server emulates its data interface.

Tag / Point ID

The unique code identifying one monitored location, such as TW-01 or MED-HOSP. Everything keys off it: readings, limits, alarms and history.

Telemetry

Measurements transmitted automatically from remote equipment, as opposed to manual reading.

SSE — server-sent events

A one-way streaming protocol over HTTP in which the server pushes updates as they occur. Used in preference to polling because it is lower-latency and lighter on both ends.

REST polling

The alternative: the client requests the current readings on a fixed interval. Simpler for a gateway to implement, at the cost of latency.

EMA — exponential moving average

Simple: a smoothing method weighting recent readings more heavily than older ones. Formula: α = 1 − e−Δt/τ, then value = previous + α(new − previous), with τ = 6 s. Why it matters: raw sensor jitter would otherwise read as plant instability.IMPL

Data quality states

Deliberately a separate axis from severity. Good — fresh sample. Pending — not heard from yet at start-up, explicitly not an alarm. Stale — over 15 s old. Offline — over 40 s old; raises a communications alarm. Bad — the meter reported bad quality, and limits are not evaluated on it.IMPL

18.3.1 The relationship

Chapter 22

Technical Findings, Glossary & Conclusion

Observations arising from the analysis, the consolidated glossary, and closing assessment.

22.1 Technical findings

F-1  Gross versus net demand inconsistency

The Total Active Power KPI displays gross site load, while the load trend chart directly beneath it plots net demand (load minus solar generation) and is labelled "Net demand". At present solar contributes under 1% of site demand, so the two differ by a negligible margin, but the labels describe different quantities. If generation capacity grows the divergence becomes material.IMPL Recommendation: align the two, or label the KPI explicitly as gross.

F-2  Solar trend is extrapolated from a single array

The generation trend on the Solar screen scales one array's history by the array count rather than summing all thirteen. Aggregate magnitude is correct and the shape is representative, but divergence between arrays will not appear in that chart. Per-array divergence is visible in the table beneath, so the information is available — but the chart alone would not reveal a single failing array.IMPL

F-3  No persistence

All readings, energy totals and alarm history exist only in browser memory. Reloading the page discards them. For a production deployment a historian would be required, both for record-keeping and to enable the trained forecast that the Forecasting screen currently cannot provide.IMPL

F-4  No authentication or authorisation

Any user reaching the URL has full access, including alarm acknowledgement. Acknowledgement is recorded against the fixed label "operator" rather than an identified user, so the audit trail records that an alarm was acknowledged but not by whom.IMPL

F-5  Every limit rests on estimated ratings

The most consequential finding. No unit kW rating is measured; all are engineering estimates, and every warning and alarm limit derives from them. The alarm logic is sound, but the thresholds it enforces are provisional until real nameplate or metered data replaces the estimates.IMPL

F-6  Documentary discrepancy in the register

The register states 14 tube wells with 12 operational, but lists 11 with locations. One operational tube well is unaccounted for. Raised with the facilities team rather than reconciled.IMPL

F-7  Items that could not be verified

  • Actual per-substation transformer allocation — not stated in the register; could not be verified from the available implementation or source document.
  • Actual feeder-to-load allocation — not stated; could not be verified.
  • Satellite station ratings — the register gives a count of 13 with no kVA; could not be verified.
  • Real breaker roles and positions — four sites are named but roles are not; could not be verified.
  • Distribution board identities — 475 stated as a total with no tags or locations; could not be verified.
  • Any historical consumption — none exists in the source document; could not be verified.

22.3 Conclusion

Power Monitor is a complete and technically sound monitoring application. Its twelve screens cover situational awareness, per-location detail, supply quality, network structure, energy analysis, generation performance, asset inventory, exception handling, reporting and forecasting. The alarm engine follows recognised industrial practice, with on-delay, hysteresis, latching, acknowledgement, ringback and anti-flood re-arm implemented and covered by automated tests.

Its architecture is deliberately minimal — no framework, no charting library, no database, no runtime dependencies — which makes it deployable by copying a folder onto an isolated network, and gives it a single well-defined integration seam at src/source.js.

Its principal limitation is not one of engineering but of input data. The source register is an asset inventory containing no measurements, so every live value is simulated and every alarm threshold rests on an estimated rating. The implementation handles this honestly: provenance is marked at the point of use, documentary discrepancies are displayed rather than hidden, and the forecast discloses its own method. That candour is the report's basis for judging the system ready for connection to real telemetry.

To move from prototype to operational service, three things are required: real metering data in place of the simulated feed; real nameplate ratings in place of the estimated ones, so the limits become defensible; and a historian, without which no record survives a page reload and no trained forecast is possible.

Summary judgement

The application is production-quality in construction and prototype-quality in data. The gap between the two is well documented within the system itself, and closing it is a data-acquisition task rather than a software one.
